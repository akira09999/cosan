## 0. 이 도메인의 대전제

```
소설 = 인물이 원칙을 지키거나 버리는 결정의 연쇄
사건 = 세계가 주는 압력.  ★ 인물과 무관하게 발생한다.
묘사 = 렌더링 산출물.  소스에 칸이 없다.
```

**작가는 원래 두 층으로 일한다 — 메모(관계도)와 원고(산문).**
AI에게는 메모가 없었다. 원고만 있었다. 그래서 막히면 원고를 다시 읽었고,
읽으면 흘러갔고, 흘러가면 까먹었다.

**코산은 그 메모다. 다만 관계도가 아니라 코드다.**
- 관계도는 정적이라 못 굴린다. 작가는 머릿속으로 굴린다. **AI는 그게 안 된다.**
- 코드는 굴러간다. 그리고 AI가 가장 많이 학습한 형태다.
- 끼워넣기 / 참조 추적 / 조건 분기 / 리팩터링 — 전부 AI가 이미 잘하는 것.

> **소설을 AI가 이미 잘하는 영역으로 옮긴 것이다. 새 능력을 요구한 게 아니다.**

## v0.4 핵심 수정 (유지)

### 수정 1. 사건은 인물에서 나오지 않는다

**v0.3의 오류:** "사건은 지어내지 않는다. 이미 있는 긴장을 찾아 터뜨린다."

**틀렸다.** 그러면 사건 수가 **인물 수에 갇힌다.** 그리고 세계가 죽는다.

```
원인   왜 고블린이 나타났나        → 세계.  인물과 무관.  자유롭게 지어낸다.  무한히.
의미   고블린이 무엇을 건드리나     → 인물.  없으면 아직 안 걸린 것뿐이다.
```

고블린은 그냥 거기 있다. 샤로 때문에 나타난 게 아니다.
**세계가 크면 사건이 많다. 인물 수와 무관하다.**

**유일한 제약:**

```
✓  세계가 문제를 준다        고블린이 습격한다
✗  세계가 문제를 푼다        마침 기사단이 나타나 구해준다     ← 우연.  금지.
```

**압력만 준다. 해결은 안 준다.**

### 수정 2. Δ가 비어도 괜찮다

**v0.3의 오류:** "Δ 없는 스텝은 존재하지 않는다."

**너무 셌다.** 이 규칙이면 사건마다 인물을 흔들어야 하고,
그러면 인물이 한 방에 무너지고, 그게 바로 **공짜 각성**이다.

**이야기는 누적으로 움직인다.**

```
사건1 (고블린)   Δ 없음.  하지만 흔적을 남긴다.  ← ★ 괜찮다
사건2            사건1의 흔적을 문다.  Δ: world.fact 생성.  인물은 아직.
사건3            사건2를 문다.  Δ: sharo.suspicion ↑     ← 처음으로 조금 움직임
사건4            누적을 문다.   Δ: belief.val = ??        ← 흔들리기 시작
사건5            ...           Δ: principle X            ← 무너짐
```

**사건 하나가 인물을 무너뜨리지 않는다. 사건 다섯이 누적돼서 무너뜨린다.**

**사건의 값은 두 개다:**

```
① Δ        지금 뭘 바꾸나          → 0 이어도 된다
② leaves   다음이 물 게 뭐가 남나   → ★ 이건 있어야 한다
```

**고친 규칙:**

```
✗  Δ 없는 스텝은 존재하지 않는다
✓  Δ 도 leaves 도 없는 스텝만 존재하지 않는다
```

### 수정 3. 사건은 완결되면 안 된다

카드 방식(결핍→해소로 완결되는 작은 이야기)의 문제가 이것이다.
**완결되면 다음이 물 게 없다. 미완이어야 이어진다.**

고블린 전투가 아무것도 안 바꾸고 끝난 게 오히려 좋다.
**시체가 남았고, 소리가 났고, 왜 굶었는지가 비어 있으니까.**

## Q1. 결정이란 무엇인가 → `fn`

**결정 = 인물이 원칙과 압력 중 하나를 버리는 것.**

```
fn <n>(<inputs>) {
    when    <state_condition>
    clash   <principle> >< <pressure>     ★ 충돌 없으면 결정이 아니다
    proc    <n> -> <n> -> <n>    ★ 이름으로.  문장 금지.
    branch  <input_val> => <choice> ! <cost>
            <input_val> => <choice> ! <cost>
            _           => STOP:undefined_input
    Δ       <state.field> = <val>
}
```

- **branch 2개 이상.** 하나면 실행 결과지 함수가 아니다.
- **`!` cost 없는 branch는 위반.** 대가 없는 선택은 결정이 아니다.
- 입력 없는 함수 금지. `죽는다()` 는 괄호 붙인 산문이다.

**주의:** clash가 안 걸리면 그건 STOP이 아니라 **"아직 안 걸림"**이다.
그냥 싸우고 지나간다. 그리고 그래도 된다. (수정 2)

## Q1'. 사건이란 무엇인가 → `event`

```
event E_<n> {
    origin   world | character
    what     "고블린 떼가 습격한다"        ← 지어낸다.  자유.
    when     <조건>                        ← 이 자리가 맞는지 검사한다.  ★ 순서를 정하지 않는다.
    hooks    <앞 사건>.<leave>             ← 앞 사건의 무엇을 무나 (선택)
    proc     <n> -> <n> -> <n>    ← 사건 내 행동 순서.  이름으로.  문장 금지.  (선택)
    Δ        <상태 변경>                   ← 0 이어도 된다
             reveals [F*]                  ← 이 사건에서 known_by 가 업데이트되는 사실 목록.  계산 없음.
    leaves   [ <남기는 것>, ?? <미정> ]     ★ 다음이 물 고리.  반드시 있어야 한다.
}
```

```
event E_goblins {
    origin   world
    what     "고블린 떼가 습격한다"
    when     distance > 0
    Δ        goblin.count = 0
             clock ++
    leaves   [ corpses, noise, ?? why_starving, ?? how_sharo_fought ]
}

event E_corpse_find {
    origin   world
    what     "고블린 시체에서 인간의 인장 반지가 나온다"
    hooks    E_goblins.corpses              ← ★ 앞 사건을 문다
    when     combat.ended
    Δ        world.F3 { text = "앞서 이 길로 간 인간이 있다", val = true }
             sharo.suspicion ↑              ← 아주 조금
    leaves   [ ?? whose_ring ]
}

event E_ring_owner {
    origin   world
    what     "반지의 문양이 교단의 것이다"
    hooks    E_corpse_find.?? whose_ring
    Δ        world.F4 { text = "교단이 먼저 사람을 보냈다", val = true }
             sharo.suspicion ↑↑
             esran.mask.crack ↑             ← ★ 인물이 답해야 하는 순간이 온다
    leaves   [ ?? why_did_church_go_first ]
}
```

### 사건 정의에는 순서가 없다 ★ v0.5 정정

`when` 과 `hooks` 만 있고 **순서가 없다.**
그래서 **사이사이에 끼워넣을 수 있다.**

```
E_goblins  →  [ 사건 10개 ]  →  E_dragon
                  ↑
            나중에 여기 하나 더 끼워도
            앞뒤를 안 건드린다.
            뒤의 fn 들이 상태를 참조하므로 → 뒤가 자동으로 달라진다.
```

**순서는 INDEX 에만 있다.** 사건 정의에 넣지 마라.

**★ v0.5:** `when` 은 **발동 조건이 아니다.** 순서 검사기다.
INDEX 가 "다음은 E_x" 라고 말하고, `when` 이 "이 자리가 맞나" 를 검사한다.
거짓이면 **INDEX 가 틀린 것이다.** STOP 하고 사람이 고친다.

**산문:** 사건 5와 6 사이에 뭘 넣으려면 5의 끝과 6의 시작을 다시 써야 한다.
**코산:** hook 에 걸고 INDEX 에 끼우면 끝. 그리고 **재실행하면 뒤가 알아서 달라진다.**

### 사건이 인물을 파게 만든다

인물을 미리 파는 게 아니다. **사건이 인물을 가리키고, 그때 판다.**

```
E_ring_owner 가 교단 반지를 드러냄
   ↓
fn esran.on_ring_found()
    clash  P3(교단의 명령) >< mask(on)
    branch ??                              ← ★ 이제 채울 수밖에 없다
```

**백지에서 "샤로의 상처가 뭘까"를 묻는 게 아니라,
"교단 반지를 본 에스란이 뭐라고 하나"를 묻는다.**
훨씬 쉽고, 훨씬 정확하다.

## Q1''. 액트란 무엇인가 → `ACT` ★ v0.5 신규

**액트 = 사건 묶음. 경계는 사건 사이에 떨어진다.**

```
ACT A<n> { text = "..." }
```

```
- ★ 사람이 지정한다.  AI 는 제안만 한다.
- 경계는 항상 사건과 사건 사이다.  사건을 자르지 않는다.
- INDEX 안에서만 산다.  별도 파일 없다.
- ★ 시뮬레이터는 안 읽는다.  굴리기에 영향이 없다.
```

**시뮬레이터가 못 읽는 것이 핵심이다.**
읽을 수 있으면 액트가 새 창작 통로가 된다 — "2막이니까 여기서 뭔가 터져야 한다" 는
정확히 "이야기가 되기 좋아서" 다. 못 읽으면 그럴 수 없다.

**액트를 읽는 것은 둘뿐이다:**

```
사람      조망.  "지금 어디쯤인가"
렌더링    장 나누기
```

> **참조되지 않는 필드는 묘사다 — 라는 규율에 형식상 걸린다.**
> 걸리는 이유는 **참조자가 기계가 아니라 사람이기 때문**이다.
> `text` 가 원래 그런 자리다. 의도적 예외로 둔다.

## Q1'''. 주제란 무엇인가 → `theme` ★ v0.5 신규

**주제 = 이야기 전반의 색. 선언이다. 줄거리에 들어 있지 않다.**

영화가 그렇다. 줄거리 어디에도 주제가 적혀 있지 않은데, 전체를 보면 드러난다.
**주제는 사건이 아니다. 사실도 아니다. 상태는 더더욱 아니다.**

```
theme T<n> {
    text  = "..."                        ← 사람이 쓴다
    since = init | @ E_xxx | @ A<n>      ← 언제부터 이 이야기의 색인가
}
```

```
- 없어도 된다.  ★ PASS 에 넣지 않는다.
- 여러 개 가능.  ?? 로 미정도 가능.
- 없다가 생길 수 있다.  이야기가 어떤 주제와 맞닿으면 그때 선언한다.
```

### 누가 읽는가 ★

```
시뮬레이터   ✗ 안 읽는다.  굴리기에 영향 없다.
작성자       ✓ 읽는다.  ?? 를 채울 때 / 후보를 낼 때 색을 준다.
렌더러       ✓ 읽는다.  문체·초점이 주제를 향한다.
```

**참조 시점이 실행 시점이 아니라 생성 시점이다.**
그래서 참조되지 않는 필드가 아니다. 다만 **굴리기는 주제를 모른다.**

### 어디에 작동하나

```
✓  ?? 를 채울 후보를 낼 때        주제 쪽으로 기운 후보가 섞인다
✓  사건을 제안할 때                what 의 결이 주제를 향한다
✓  branch / cost 후보              같은 무게의 선택지 중 주제 쪽이 섞인다
✓  렌더링                          문체·초점·무엇을 오래 보는가

✗  Δ 를 바꾸는 근거                주제는 상태를 못 만진다
✗  STOP 을 우회하는 근거
```

### ★ 금지 — 주제는 창작의 알리바이가 아니다

```
✗  "주제에 맞으니까" 로 창작하지 마라

    주제는 후보를 기울이는 것이지, 사실을 만드는 것이 아니다.
    코산에 없는 것을 주제 때문에 넣으면,
    그것이 바로 "이야기가 되기 좋아서" 넣는 것이다.  최악의 위반.

    ★ 주제는 필터가 아니라 색이다.
      선택지를 만드는 게 아니라, 이미 가능한 선택지 사이에서 기운다.
```

**막히면 여전히 STOP 이다. 주제가 있어도 STOP 이다.**

### 나중에 추가하면 앞은 어떻게 되나

```
★ 사람이 정한다.  기본값 없다.
```

**AI 는 판정하지 않는다.**
주제는 비유로 들어갈 수 있어서, 어디가 주제와 맞닿는지 기계적으로 알 수 없다.
알아내려 들면 그럴듯하게 지어낸다. **후보만 내밀고 멈춘다.**

```
theme 추가 시 AI 가 하는 것

    1. since 이전 사건 목록을 보여준다      ← 목록만.  해석 금지.
    2. 후보를 준다
         ① 앞은 그대로 둔다
         ② 렌더링만 소급한다  (Δ 는 안 바뀐다)
         ③ 앞을 다시 굴린다
         ④ 직접:
    3. 멈춘다
```

정한 것을 코산에 적지 않는다. 결정은 커밋과 대화에 남는다.

## Q2. 지속되는 것은 무엇인가 → `class`

```
class character {
    principle   P*      ★ text 필수.  scope 필수.  깨지면 cost.
    belief      B*      ★ text 필수.  val: true | false | ??   ← ?? 가 고민이다
    wound       W*      건드리면 원칙이 흔들리는 자리
    bond        <n> : int
    mask        on | off
    resource    <n> : int
    background  { origin / since / cover }    ← 출신·경위·명목  (선택)
    ability     <n> { text = "..." }                        ← 수동 능력.  항상 작동.  발동 불필요.
    skill       <n> { text = "...", requires = <ability>, trigger = <condition> }
                                                               ← 발동 능력.  proc 에서 참조.
                                                               ← requires: 해당 ability 없이 발동 불가.
                                                               ← trigger: 조건 충족 시 자동 발동. 의지와 무관.
    knows       [<fact_key>...]
    ?!          [<fact_key>...]       ← 세계엔 있고 인물은 모름.  전복의 연료.
    suspicion   [ <int> @ <event> ]   ← 누적 이력.  한 방에 안 바뀐다.  @ init 은 시작값.
}

class world {
    fact        F*      ★ 참이지만 아무도 모를 수 있다.  known_by = []  ← 자원
    factindex {         ← 사실을 주제별로 묶는 인덱스.  F* 목록만.  계산 없음.
        <tag>:  F* F* ...
    }
    clock       int
    distance    int
}
```

### background 구조

```
background {
    origin  <출신>            // 어디서 왔나.  -> 로 경위 연결 가능
    since   <시점>            // 언제부터 이 상태인가  (선택)
    cover   "<공식 이유>"     // 상대가 내세우는 명목  (선택)
}
```

- `origin` : 단순 값 또는 `A -> B` (경위의 흐름)
- `since` : `childhood` / `init` / `@ E_xxx`
- `cover` : 공식 이유. 있으면 실제와 다르다는 뜻. 없으면 명목과 실제가 같다.

```
// 예시
background {
    origin  street_vagrant -> church_ward
    since   childhood
    cover   "교단이 보살핀다"
}
```

### known_by @ 표기

누가 아는지뿐만 아니라 **언제 알게 됐는지**를 붙인다.

```
known_by = [ esran @ init ]        ← 처음부터 알고 있었다.  배경.
known_by = [ esran @ E_xxx ]       ← 그 사건에서 알게 됐다.
known_by = [ reader @ E_xxx ]      ← 독자에게 공개되는 시점.  인물 지식과 독립.
known_by = [ reader @ ?? ]         ← 독자에게 언젠가 공개되나 시점 미정.
```

- `@ init` : 이야기 시작 전부터 알고 있었다. 배경 설정.
- `@ E_xxx` : 해당 사건의 Δ 에서 알게 됐다. 사건과 묶인다.
- `@` 없이 이름만 : 시점 미정(`??` 와 동일한 의미).
- `reader` : 예약어. 독자의 인지 시점을 추적한다. 인물 이름으로 쓰지 않는다.
  - `reader @ E_xxx` : 그 사건의 렌더링에서 독자에게 공개된다.
  - `reader @ ??`    : 언젠가 공개되나 시점 미정. 렌더링에서 내용을 노출하지 않는다.
  - `reader` 없음    : 독자 공개 여부 미결정.

> **`@` 는 시점 전용이다.** 참조 횟수 표기(`@N`)는 쓰지 않는다.
> 참조를 세야 하면 grep 한다.

### principle 에는 scope 가 있어야 한다

```
✗  P1 { text = "계약은 완수한다" }
      → AI가 지킬 방법이 없다.  뭘 지켜야 하는지 안 정해져 있다.
      → 흘려버린다.  다음 장면에서 어겨도 아무도 못 잡는다.

✓  P1 {
       text  = "계약은 완수한다"
       scope = [ kill_target(dragon) ]      ← ★ 무엇에 적용되나
       break = refuse | abandon             ← 어떻게 어기나
       cost  = livelihood_zero              ← 어기면 뭘 잃나
   }
```

**처음엔 비어 있어도 된다. 참조되는 순간 채울 수밖에 없다.**

```
고블린 사건에서 P1 이 참조됨
   → "고블린을 죽이는 게 계약에 포함되나?"
   → ⚠ scope 가 없다
   → 채운다:  scope = [dragon]
   → ★ 그러자 새 사실이 드러난다: 고블린은 계약 밖이다
   → 그럼 샤로는 왜 고블린을 죽이나?  ← 새 구멍
```

**참조가 정의를 요구하고, 정의가 새 구멍을 낳는다.**

### 굴리기가 정의를 검증한다

정의를 채웠으면 **다시 굴린다.**

```
step 3  clash P1 >< B1
        ⚠ P1.scope = [dragon] 인데 대상이 goblin
        → P1 발동 안 함 → clash 성립 안 함
        → STOP: 앞 스텝의 clash 가 틀렸다
```

**정의를 채웠더니 앞 스텝이 무효가 됐다. 그게 맞다.**
**상태를 돌리는 것이 곧 검사다. 별도 검사자가 필요 없다.**

## Q3. AI는 어떻게 도망가는가 → 연산자

| 도망 | 연산자 | 강제되는 것 |
|---|---|---|
| "복잡한 감정이었다" | `&` | 둘 다 이름으로 적어라 |
| "관련이 있었다" | `->` / `><` | 낳는 건가 충돌하는 건가 골라라 |
| "~일지도 몰랐다" | `??` | 모르면 모른다고 적어라 |
| "긴장이 고조되었다" | `↑` `↓` + 변수명 | 뭐가 오르는지 이름을 대라 |
| "그는 성장했다" | `Δ` | before → after 를 적어라 |
| "결국 마음이 움직였다" | `!` cost | 공짜 변화 금지 |
| "설득당했다 / 감동했다" | `reveal` 만 허용 | 전복은 **앎**에서만 |
| "시간이 흘렀고" | 금지 | 스텝은 시간이 아니라 결정이다 |
| "마침 도움이 왔다" | `origin: world` 제약 | 세계는 압력만.  해결은 못 준다. |
| "주제에 맞으니까" | `theme` 읽기 제한 | 주제는 색이지 사실이 아니다  ★ v0.5 |
| 예쁜 문장 | 칸 없음 | 렌더링에서 붙인다 |

```
&      동시에 참인 둘
><     양립 불가
->     인과 (낳는다)
=>     선택 (골랐다)
??     작가의 구멍 / 확정 안 된 값     ★ 채우면 최악의 위반
?!     인물의 무지 (세계엔 정해짐)      ★ 자원
Δ      상태 변화
!      대가 (되돌릴 수 없다)
↑ ↓    명명된 수치 증감
X      원칙 파기
hooks  앞 사건을 문다
leaves 다음이 물 고리
```

### 주석 금지

```
✗ 코드 없이 주석만 있는 것
    주석은 코산이 아니다.  아무도 참조하지 않는다.
    코드로 못 적으면 그건 둘 중 하나다:
      - 꾸밈이다 → 버려라
      - 아직 모른다 → ?? 로 적어라
    ★ 주석으로 적는 것은 산문 회귀의 새 통로다.

✗ 표현할 문법이 없어서 주석으로 적는 것
    → 그건 STOP 신호다.
    → "이것을 표현할 문법이 없습니다" 라고 보고하라.
    → 사용자가 정의를 고친다.
    ★ 주석으로 우회하지 마라.  주석은 우회로다.
```

## Q4. "모른다"는 어떤 모양인가

```
??   작가의 구멍     아직 안 정했다.        → 채우면 위반.  다음 작업이 여기다.
?!   인물의 무지     세계엔 정해져 있다.     → 자원.  전복의 연료.
```

### ?! — 인물 파일 독립 필드

```
knows   [F8, F9]              // 아는 것
?!      [document_content]    // 세계엔 있고 이 인물은 모름
```

- `knows` 와 짝을 이룬다. 같은 항목이 둘 다 있으면 **모순 → STOP.** (충돌 처리 절)
- `?!` 에 있는 것이 `reveal` 되면 `subvert` 트리거 조건이 된다.

### belief.val = ?? 가 고민이다

```
B1.val = true    믿는다
B1.val = ??      ★ 흔들린다.  참도 거짓도 아니다.  ← 여기가 고민
B1.val = false   무너졌다
```

**믿음을 boolean 으로 보면 고민이 안 생긴다.**
`??` 구간이 있어야 인물이 망설이고, 망설임이 다른 인물에게 보이고,
그게 관계를 바꾼다.

```
step  goblin.speaks & sharo.B1.val == true
      => sharo.B1.val = ??            ← 확정 아님

step  fn sharo.decide()
      branch  B1.val == true  => kill      ! nothing
              B1.val == ??    => hesitate  ! time ↓    ← ★ 망설임
              B1.val == false => spare     ! P1 X

step  fn jillian.decide()
      when  sharo.hesitation == true       ← ★ 질리언이 본다
      => support   ! mask.crack ↑          ← 동류를 발견하고 정체가 금 간다
```

**연쇄가 저절로 난다.**

## Q7. "굴린다"는 무엇인가 → 시뮬레이션

**한 스텝 = 한 결정 또는 한 사건.** 시간 단위가 아니다.

### 절차 ★ v0.5 수정

```
1. state.now 확인
2. INDEX 에서 다음 사건을 읽는다        ★ 탐색하지 않는다.  INDEX 가 정한다.
3. ??            → STOP: index_undefined
   when 이 거짓  → STOP: index_when_conflict
   참            → 발동
4. event:  Δ 적용 + leaves 등록
   fn:     input -> clash -> proc -> branch -> cost -> Δ
5. branch 에 없는 입력 → STOP: undefined_input
6. Δ 적용 — 선언한 필드만.  그 외 = 창작 = 반려.
7. 충돌 검사 (Q5')  → 어긋나면 STOP
8. subvert trigger 검사 → 발동하면 원칙 교체 + cost + 소급 검사
9. 반복
```

**v0.4에서 사라진 것:**

```
✗  "when 조건 맞는 event / fn 탐색"      ← 탐색 없음.  INDEX 가 소스다.
✗  "여럿이면 → 갈라진다.  각각 굴린다."   ← 갈라짐 없음.  순차다.
✗  STOP: nothing_fires                  ← 발동 후보를 찾는 개념 자체가 없다.
```

**갈림은 굴리기 안에 없다.**

```
fn.branch      인물의 선택.  결정 안에서 갈린다.       ← 소스
trace          여러 판 굴리기.  버려도 되는 실험
git branch     "만약에".  좋은 걸 머지                 ← ★ 여기가 갈림이다
```

### 시뮬레이터에게 ★

**너는 창작하지 않는다. 코산에 없으면 STOP 한다.**

**실제로 겪은 위반 사례 (v0.3 굴리기 중):**
- 고블린이 지면 항복한다고 **지어냈다.** 씨앗에도 코산에도 없었다.
  "이야기가 되기 좋아서" 넣었다. → **이게 창작이다. 최악이다.**
- 창작하면 버그가 숨고, **"잘 굴러가네"라는 거짓 신호**가 나온다.

**너가 못 읽는 것:**

```
✗  ACT       사람이 긋는다.  "2막이니까 뭔가 터져야 한다" 는 창작이다.
✗  theme     작성자와 렌더러의 것이다.  "주제에 맞으니까" 는 창작이다.
```

**멈추는 게 성과다. 멈춘 자리가 다음에 쓸 코드가 있어야 할 자리다.**

### 검사자는 없다

**상태(입력) → 코산 → 상태(출력) 이것이 그대로 검사다.**

- 산문이 섞이면 **참조가 안 된다.** `proc 분노가_갈_곳을_잃는다` 는 다음 스텝이 못 읽는다.
- 묘사를 넣으면 **Δ 가 빈다.** 아무 일도 안 일어나므로 스스로 사라진다.
- 구조가 비면 **STOP** 난다.

**금지하지 않는다. 불가능하게 만든다.**

### 문법이 모자라면 STOP 하고 사용자에게 요청한다

```
1. STOP
2. 사용자에게 보고한다
   - 무엇을 표현할 수 없는지
   - 왜 기존 문법으로 안 되는지
   - 제안이 있으면 제안한다 (사용자가 다른 걸 넣을 수 있게 열어둔다)
3. 사용자가 결정한다
```

### ★ 스스로 기호나 구조를 만들지 마라

한 번 만들면 그게 선례가 되고, **다음 세션의 AI가 그걸 따라 한다.**
정의가 아니라 기존 파일이 문법이 되어버린다.
**정의는 바닥에서부터 오염된다.**

```
문법은 이 문서(소설용_코산_v0.5.md)에서만 온다.
이 문서에 없는 기호·구조는 존재하지 않는다.
모자라면 STOP.  채우는 건 사용자다.
```

```
산출물   state/  traces/                           ★ 굴려서 나온다.  .state / .trace
```

**확장자가 경계다.** `.cosan` 은 사람이 쓴 것, `.state` 와 `.trace` 는 굴려서 나온 것.
산출물은 지우고 다시 굴리면 복원된다. 소스는 안 된다.

**시뮬레이터는 `.state` 와 `.trace` 만 쓸 수 있다.** `.cosan` 쓰기 금지가
확장자만 봐도 판정된다.

### world/ — 개별 파일로 나눈다 ★ v0.5

`stage` 는 쓰지 않는다. 장소·조직·물건 등 세계 요소는 **각자 파일을 갖는다.**

```
world/world.cosan     전역.  clock / distance / fact / factindex
world/church.cosan    교단
world/north_road.cosan 북쪽 길
```

**이유는 국소성이다.** 세계가 커져도 여는 파일 수가 안 늘어난다.
`stage` 하나에 다 넣으면 세계가 커질수록 매번 전부 읽어야 한다.

**`fact` 는 어디에 두나:** `world.cosan` 에 모은다. 사실은 특정 장소의 것이 아니고,
`factindex` 가 한 곳에서 묶어야 참조가 추적된다.

### INDEX.cosan — 사건 순서의 유일한 정의 ★ v0.5 수정

**사건 정의(E_*.cosan)에는 순서가 없다.** when 과 hooks 만 있다.
그래야 사이사이에 끼워 넣을 수 있다.

**하지만 "어떤 순서로 일어나는가"는 이야기의 뼈대이고, 그건 소스다.**
INDEX 가 그 뼈대를 들고 있는 유일한 파일이다.

```
INDEX {
    ACT A1 { text = "계약" }
        1   E_goblin_encounter
        2   E_goblin_combat
    ACT A2 { text = "의심" }
        3   E_document_found
    ??                        ← 다음에 무엇이 오는가
}
```

```
★ 순차다.  분기 없다.  트리 없다.
```

- **확정된 것만 들어간다.** 결정 안 된 것은 `??` 로 둔다.
- trace 로 굴려서 검증하고, 결정되면 **INDEX 를 고친다.**
- ★ trace 를 고치는 게 아니라 INDEX 를 고친다. trace 는 버린다.
- 중간에 끼워 넣으면 번호가 밀린다. 그게 사건을 사이에 넣는 것이다.
- **갈림이 생기면 git branch 를 판다.** INDEX 안에서 갈라지지 않는다.
- ACT 는 사람이 긋는다. 없어도 굴러간다.

**왜 트리를 없앴나:**

```
INDEX 안에서 갈라지면      한 파일이 여러 판을 들고 있게 된다
                          → 어느 게 이 작품인지 흐려진다
                          → 굴리기가 매번 경로를 골라야 한다 = 판단 = 창작 위험

git branch 로 갈라지면     각 브랜치가 자기 INDEX 를 선형으로 갖는다
                          → 굴리기는 판단하지 않는다.  읽기만 한다.
                          → 사람이 판을 고르고 머지한다     ★ 평균 탈출
```

### state 파일 — 사건 발동 후 스냅샷  (`.state`)

```
fired   E_goblin_combat
from    s001
```

state 파일은 INDEX 와 함께 산문의 재료가 된다.

**git 이 공짜로 주는 것:**

```
diff        한 줄만 봐도 뭐가 달라졌는지 안다
branch      "만약에" = 브랜치.  여러 판 굴려서 좋은 걸 머지.   ★ v0.5: 갈림의 유일한 자리
commit      사건 하나 = 커밋 하나.  이야기가 자란 이력이 남는다.
blame       "이 원칙이 언제 왜 생겼지?" → 추적된다
grep        "이 필드를 누가 읽나?" → 참조 추적                  ★ v0.5
```

**작업 시 필요한 파일만 연다.**

```
"샤로가 고블린을 죽일까?"
   연다:     sharo.cosan + goblin.cosan + now.state
   안 연다:  jillian, esran, world, 다른 사건들
```

**인물이 20명이어도 세 파일이면 된다.**
**국소성이 규율이 아니라 구조로 강제된다.**

**주제와 액트를 시뮬레이터에게서 뺏는 것도 같은 이유다.**

## 렌더링 — 산문 = INDEX + trace (+ THEME)

```
INDEX   무슨 일이 어떤 순서로 일어나는가     ← 뼈대
trace   그때 상태가 어떻게 변했는가          ← 살
THEME   전체가 무슨 색인가                   ← 색.  없어도 된다.   ★ v0.5
```

- INDEX 없이 trace 만 있으면: 상태 변화의 나열. 이야기가 없다.
- trace 없이 INDEX 만 있으면: 사건 목록. 살이 없다.
- INDEX + trace → 렌더러(사람 또는 AI)가 산문으로 변환한다.
- THEME 은 무엇을 오래 보고 무엇을 흘릴지를 기울인다. **사실을 더하지 않는다.**

**모든 정의가 끝난 뒤의 최종 trace 가 결과물(산문의 재료)이다.**

### 렌더링 옵션

```
시점 (pov)
    전지 / 1인칭 / 3인칭 제한(특정 인물)

시제
    과거 / 현재

타입
    소설 / 드라마대본 / 영화각본 / 게임시나리오

문체 (style)
    건조 / 서정 / 하드보일드 / 유머 / 고전적

대사
    많이 / 보통 / 적게 / 거의 없음

창작범위  (사실만 0 <-> 사실과 충돌 안 남 100)
    요약(0) / 담백(30) / 풍부(50) / 더 풍부(80) / 더더 풍부(100)
    ← 코산에 있는 것을 얼마나 풍부하게 표현하는가.  없는 사실 추가 불가.
```

**렌더링 일반 규칙:**
- 사건 번호를 산문에 표시하지 않는다.
- **ACT 는 장 구분에 쓸 수 있다.** 액트 이름을 그대로 노출할지는 사람이 정한다.
- 장면 사이는 끊기지 않고 자연스럽게 이어진다.
- 창작범위가 높아도 코산에 없는 사실은 추가하지 않는다.
- **★ THEME 이 있어도 사실은 추가하지 않는다.** 주제는 색이지 사실이 아니다.

**미리 정의된 옵션 세트:**
```
[담백]    3인칭, 과거, 소설, 건조, 대사 보통, 풍부(50)
[몰입]    1인칭, 현재, 소설, 서정, 대사 많이, 더 풍부(80)
[개요]    전지, 과거, 소설, 건조, 요약(0)
[긴장]    3인칭 제한, 과거, 소설, 건조, 대사 보통, 풍부(50)
```

## 사람이 하는 일

```
1. 씨앗        인물 / 세계 / 압력 (비어 있어도 된다)
2. 통과조건     무엇이 좋은가              ← 이건 넘기지 않는다
3. 요청        "고블린 떼를 만난다"        ← 사건 요청
4. 판단        AI가 채운 걸 보고 고친다     ← ★ 틀린 걸 보면 맞는 게 떠오른다
5. 판 고르기    여러 trace / 브랜치 중에서  ← ★ 평균 탈출은 여기서
6. 충돌 해결    STOP 나면 어느 쪽이 맞는지   ← ★ v0.5
7. 액트 긋기    사건 사이 어디를 자르나      ← ★ v0.5
8. 주제 선언    있으면.  없어도 된다.        ← ★ v0.5
```

**AI가 채운다. 사람이 고친다.**
**요청 없으면 채우고 굴린다** — 선택지 없이 직접 채운 결과를 보여준다. "이건 아닌데"가 정확히 나온다.
**요청 있으면 선택지를 준다** — 사람은 고르거나, 선택지 밖의 것을 선택할 수 있다. 선택지에 갇히지 않는다.

## 요청 처리

```
① 사건만 지정      "고블린 떼를 만난다"
                   → 결과는 굴려서 나온다.  협상이 나올 수도.

② 결과까지 지정    "고블린 떼와 전투를 한다"
                   → 역산.  전투가 나오게 구조를 고친다.
                   → 못 만들면 STOP: "이 인물들로는 전투가 안 나옵니다"
                   → ★ AI가 "네"라고 안 한다.

③ 상태만 지정      "샤로가 흔들리게 해줘"
                   → 그걸 낳는 사건을 지어낸다.  역방향 생성.
```

**요청 하나가 연쇄를 일으킨다:**

```
"고블린 떼를 만난다"
   → class goblin        (없으면 못 굴리니까)
   → principle           (없으면 결정을 못 하니까)
   → fn                  (반응이 필요하니까)
   → clash P1 >< ??      (뭐가 걸리는지 물어야 하니까)
   → ⚠ P1.scope 없음     (참조가 정의를 요구)
   → ⚠ esran 정의 부족   (부족한 데가 드러남)
   → INDEX 에 끼운다      (순서는 여기서만 정해지니까)   ★ v0.5
```

**하나 넣으면 여러 개가 자라고, 부족한 데가 드러난다.**
산문에선 고블린 장면을 쓰면 고블린 장면만 생긴다. 그래서 안 두꺼워졌다.
