# META 코산 v0.3

> **영문명: COSAN** (Coding + 散文/prose)
> 항상 `COSAN` 으로 표기한다. `KOSAN` 이 아니다.
> 파일 확장자: `.cosan`

> 이 문서를 AI에게 주면, AI는 이것을 읽고 **도메인용 코산 정의**를 만든다.
> 메타코산은 도메인 문법을 정의하지 않는다. 문법을 만들 수 있는 **원리 · 물음 · 강제**만 담는다.

```
메타코산  →  (AI에게 준다)  →  <도메인>용 코산 정의  →  <도메인> 코산  →  굴린다  →  trace
```

**v0.2 변경점:** 코드화 강제(6절)를 추가했다.
v0.1로 생성했더니 결과물이 **산문과 코드의 중간**에서 멈췄다.
껍데기만 기호고 값은 자유 문장이었다 — 그 칸으로 산문이 되돌아온다.

---

## 1. 정의

> **코산 = 생각을 코드 형태로 적은 것. 실행기는 사람 또는 AI. 코드 자체가 결과물.**

**① 생각을 코드 형태로 적는다**
- 대상이 아니라 **대상에 대한 생각**을 적는다.
- 코드 형태 = 입력/과정/출력이 명시되고, 조건에 따라 답이 갈리고, 관계가 기호로 못 박힌다.
- 산문이 아닌 이유: **산문은 결정을 안 해도 분량이 나온다.**

**② 실행기는 기계가 아니다**
- 컴파일러가 없다. 그래서 문법이 **정확할** 필요는 없다.
- (단, **코드처럼 보일** 필요는 있다. 6절.)
- 실행의 목적은 답을 얻는 게 아니라 **무너지는 데를 찾는 것.**

**③ 코드가 결과물이다**
- 코드가 **소스이자 기억이자 결과물.**
- 산문·합의문은 나중에 코드에서 **렌더링**한다. 빌드 산출물이다.

### 코산이 아닌 것

```
✗ 프로그래밍 언어      컴파일러가 없다. 실행이 목적이 아니다.
✗ 구조화된 산문        껍데기만 기호고 값이 문장이면 코산이 아니다.  ← 가장 흔한 실패
✗ 시간순 사건 나열      그건 실행 결과(trace)다.
✗ 명세서 / 설계도      굴릴 수 없으면 코산이 아니다. 굴러야 한다.
✗ 데이터 / 설정        결정이 없으면 코산이 아니다.
```

### 최소 조건

```
결정      입력에 따라 답이 갈리는 것       없으면 → 설정 파일
상태      결정이 바꾸는 것                없으면 → 규칙 목록
통과조건   무엇이 좋은가                   없으면 → 평균 생성기
```

## 2. 왜 있는가

AI는 산문에서 **얕아진다.**

**① 수식어는 회피다**
구조를 안 정해도 분량이 나오는 유일한 방법이 꾸미는 것이다.
"차가운 바람이 옷깃을 스쳤다"는 아무것도 결정하지 않고 한 줄을 채운다.
리스크 없이 분량이 나오므로 AI에게 이건 **최적 전략**이다.
결과: 문장은 늘어나는데 아무 일도 안 벌어진다.

**② 평균은 제약이 없을 때 나오는 답이다**
조건이 안 걸린 문제에 답을 내라 하면, 가장 그럴듯한 것 = 가장 흔한 것이 나온다.
여러 AI를 토론시켜도 마찬가지다. **약간씩 다르게 인출**할 뿐 진짜로 생각하지 않는다.
산문엔 **틀릴 수 있는 자리가 없다.** 인상은 반박이 안 된다.

**③ 결과물과 기억이 분리되면 기억은 손실된다**
기억(요약)은 결과물의 파생물이고, 파생물은 원본보다 항상 못하다.
그리고 이미 쓴 산문은 **앵커**가 되어, 고쳐도 비슷한 것만 나온다.

> **∴ 얼버무릴 수 없고, 고칠 수 있는 매체가 필요하다.**

## 3. 원칙

> **금지하지 않는다. 불가능하게 만든다.**

```
꾸미지 말라고 시키지 않는다      →  꾸밀 칸을 없앤다
평균을 금지하지 않는다           →  평균이 통과 못 하는 관문을 세운다
기억력을 늘리지 않는다           →  기억할 필요를 없앤다
일관성을 지키라고 하지 않는다     →  어기면 검출되게 한다
산문 쓰지 말라고 하지 않는다     →  문장을 쓸 칸을 없앤다      ← 6절
```

**규칙으로 시키면 어긴다. 구조로 막으면 못 어긴다.**

## 4. 어떻게 하는가

### ① 결정만 받는다

**왜 그랬는지 + 그래서 뭐가 바뀌는지.** 둘 다 없으면 못 들어온다.

> **코산에 못 들어가는 것은 없어도 되는 것이다.**

이건 배제 규칙이 아니라 **판정 도구**다.

```
"이걸 코산에 적을 수 있나?"
   적을 수 있다  →  구조다.  본체다.
   적을 수 없다  →  둘 중 하나다:
                    (a) 꾸밈이다        → 버린다. 필요하면 렌더링에서 살로 붙는다.
                    (b) 아직 모른다      → 구멍으로 남긴다. 채우지 않는다.
```

**(a)와 (b)를 반드시 구별하라.** 섞으면 모르는 것을 꾸밈으로 덮게 된다.

- 못 적히는 게 **꾸밈**이면: 없어도 된다. 이야기도 논증도 안 무너진다.
- 못 적히는 게 **모름**이면: 없으면 안 된다. 구멍으로 명시해야 다음 작업이 정해진다.

**문장은 이 판정을 무력화한다.** 문장은 꾸밈과 모름을 똑같이 그럴듯하게 덮어버린다.
그래서 6절(코드화 강제)이 필요하다.

### ② 얼버무림을 연산자로 막는다

**AI가 도망가는 표현을 찾아라. 하나마다 "그럼 정확히 뭐냐"를 묻는 기호를 둬라.**

```
"복잡한 감정"       →  A & B      (뭉개지 말고 둘 다 적어라)
"관련이 있다"       →  -> 또는 ><  (낳는 건가 충돌하는 건가 골라라)
"~일 수도 있다"     →  ??         (모르면 모른다고 적어라)
"긴장감이 고조된다"  →  ??? ↑      (뭐가 올라가는지 적어라)
```

**연산자를 쓰려면 골라야 한다. 고르는 그 순간이 깊이다.**
→ 연산자 목록 = **AI가 도망칠 구멍을 막은 목록.**
→ 연산자는 문법에서 뽑지 말고 **얼버무림에서 뽑는다.**

### ③ 모르는 것은 모른다고 적는다

채우면 위반. **구멍이 보여야 다음 작업이 정해진다.**
AI는 자유를 주면 무조건 그럴듯하게 채운다. 채울 자리를 **합법화**해야 안 채운다.

### ④ 기억을 AI 밖에 둔다

```
상태N  →  [코산]  →  상태N+1
```

AI는 **아무것도 기억하지 않는다.** 요약하지 않는다. 요약은 손실이다.
코산은 이미 압축이다(꾸밈이 애초에 안 들어와서). 더 짜낼 게 없다.
한 스텝에 필요한 건 **상태 + 발동할 함수 몇 개**뿐 → **컨텍스트가 상수로 유지된다.**

### ⑤ 굴려서 터뜨린다

```
실행해서 결과를 얻는다   ✗
실행해서 버그를 찾는다   ✓   ★
```

**시뮬레이터는 창작하지 않는다. 코산에 없으면 STOP 한다.**

- "굴려봐"라고 하면 AI는 그냥 결과물을 써버린다. 막힌 데를 우회하고 구멍을 메운다.
- 그러면 버그가 숨고, **"잘 굴러가네"라는 거짓 신호**가 나온다. 최악이다.
- **멈추는 게 성과다.** 멈춘 자리가 다음에 쓸 코드가 있어야 할 자리다.
- 상태 갱신은 **함수가 선언한 것만** 가능하다. 그 외 변경 = 창작 = 반려.
- **AI를 창작자가 아니라 인터프리터로 강등시킨다.**

### ⑥ 고치고 다시 굴린다. 다시 쓰지 않는다

```
산문 수정:  기존 텍스트 → AI가 고침 → 기존 텍스트에 끌림 → 비슷함
코산 수정:  규칙 변경   → 재실행    → 이전 결과 안 봄     → 다름
```

**재생성이 아니라 재실행.** 앵커가 없어서 진짜로 달라진다.
temp를 올릴 필요도 없다. 랜덤한 차이가 아니라 **인과적인 차이**다.

### ⑦ 통과 조건은 사람이 쓴다

무엇이 "조건에 맞는 답"인지는 **판단**이다. 판단은 AI에게 넘기지 않는다.

> **평균이 왜 나왔는가 — 통과 조건이 없어서.**
> 통과해야 할 게 없으니 아무거나 통과했고, 아무거나 통과하면 가장 흔한 게 나온다.

## 6. 코드화 강제 ★ (v0.2 신규)

> **코산은 코드처럼 보여야 한다. 예뻐서가 아니라, 안 그러면 산문으로 돌아가기 때문이다.**

### 6-1. 왜 필요한가

메타 v0.1로 도메인 코산을 생성했더니 이렇게 나왔다:

```
과정:  때릴 대상이 없다 -> 분노가 갈 곳을 잃는다 -> 자기에게 꺾인다
```

껍데기(`과정:`, `->`)는 기호인데 **값이 완전한 문장**이다.
서술어가 있고, 은유가 있고, 읽으면 그냥 소설이다.

**이 칸으로 산문이 되돌아온다.** AI는 자유 문장 칸을 발견하면 거기에 문장력을 쏟는다.
조금씩 길어지고, 결국 코산이라는 이름의 산문이 된다.

**형태가 사고를 끌고 간다.** 코드처럼 생기면 코드처럼 생각하고,
한국어 문장처럼 생기면 한국어 문장 생성 회로가 켜진다.

### 6-2. 규칙 — 값은 이름이다

```
✗  분노가 갈 곳을 잃는다        서술어. 문장. 죽은 텍스트.
✓  anger.target = null         이름. 참조 가능. 살아 있음.
   anger.dir    = self
```

**문장은 죽어 있고, 이름은 살아 있다.**

- 문장은 아무도 못 잡는다. 검사자도, 다음 함수도, 다음 스텝도.
- 이름은 참조된다. 다른 함수의 입력이 되고, 검사자가 "이게 한 번도 안 바뀌었다"를 잡는다.

**코드처럼 보여야 하는 진짜 이유 — 참조 가능해야 해서.**

### 6-3. 두 층 — 키와 텍스트

전부 영문 기호로 만들면 사람이 못 읽는다 (`minho_1_3_input`).
전부 한글 문장으로 두면 산문으로 돌아간다.

**갈라라.**

```
key    영문 snake_case.  코드가 참조하는 것.  AI가 조작한다.
text   따옴표 안 자연어.  사람이 읽는 것.     AI가 조작 금지.
```

```
belief B1 {
    key  = father_protects_me           // 코드가 만진다
    text = "아버지는 나를 지킨다"          // 사람이 읽는다
    val  = true                          // 틀릴 수 있다
}
```

**따옴표가 경계선이다. 따옴표 안은 사람 영역, 밖은 코드 영역.**
**따옴표 안에만 자연어가 허용된다.**

### 6-4. 텍스트를 어디에 붙이나

전부 붙이면 코산이 두 배가 된다. **판단이 필요한 곳에만 붙인다.**

```
텍스트 필수     사람이 무게를 재야 하는 것
                (도메인마다 다르다 — 원칙, 믿음, 대가, 주장, 근거 등)

텍스트 생략     읽으면 아는 것
                pressure = 4    resist = false    anger.dir = self
```

**중요한 건 몇 개 안 된다.** 텍스트가 열 개를 넘어가면 그건 산문으로 새고 있다는 신호다.

### 6-5. 골격은 영문

```
class  fn  if  else  =  ==  null  true  false  ??  Δ  cost  ...
```

구조 키워드를 영문으로 두면 AI가 **코드 모드**를 유지한다.
도메인 값은 한글이어도 된다 — **단, 이름이어야 한다.**

```
✓  principle P1 { text = "가족을 판 놈이 되지 않는다" }
✓  anger.dir = self
✓  belief.아버지가_나를_지킨다 = false      // 언더스코어로 묶인 이름. 문장 아님.
✗  분노가 갈 곳을 잃는다                    // 띄어쓰기 + 서술어 = 문장
```

**띄어쓰기가 문장의 시작이다.** 따옴표 밖에서는 띄어쓰기를 금지하라.
이름은 언더스코어로 묶는다.

### 6-6. 검사 (기계적으로 잡힌다)

```
□ 따옴표 밖에 조사가 있는가        (은/는/이/가/을/를/에/로)   → 문장이다. 위반.
□ 따옴표 밖에 서술어가 있는가       (~다 / ~한다 / ~된다)      → 문장이다. 위반.
□ 따옴표 밖에 띄어쓰기가 있는가                                → 문장이다. 위반.
□ key 없이 text만 있는 요소가 있는가                          → 참조 불가. 위반.
□ text가 지나치게 많은가                                     → 산문으로 새는 중.
```

**앞의 셋이 산문 회귀 탐지기다. 정규식으로도 잡힌다.**

### 6-7. 이 강제가 4절①을 살린다

문장을 허용하면 **"코산에 못 들어가는 건 없어도 되는 것"이라는 판정이 무력화된다.**
문장은 뭐든 받아주기 때문이다 — 꾸밈도, 모르는 것도, 똑같이 그럴듯하게.

**이름만 허용하면 판정이 다시 작동한다.**

```
"이걸 이름으로 적을 수 있나?"
   적을 수 있다   →  구조다
   못 적겠다     →  꾸밈이거나, 아직 모르는 것이다
                    → 꾸밈이면 버려라
                    → 모르는 것이면 ?? 로 남겨라
```

**이름으로 못 적히는 걸 문장으로 적는 순간, 모른다는 사실이 숨는다.**

## 7. 도메인 코산 만들기 — 답하면 그게 그 도메인의 문법이다

### Q1. 이 도메인에서 "결정"이란 무엇인가?
→ **함수**가 된다.
- 입력 / 과정 / 출력이 다 있어야 한다.
- **분기를 전부 적어야 한다.** 하나만 적으면 그건 실행 결과다.
- 과정이 곧 인과다. 과정 없는 매핑은 판단할 수 없다.
- **과정도 이름으로 적어라.** (6절) 문장으로 적으면 그 칸이 산문 통로가 된다.

### Q2. 이 도메인에서 지속되는 것은 무엇인가?
→ **클래스와 상태**가 된다.
- 시간을 건너 계속 참인 것.
- **주의:** 상황별로 함수를 만들면 "그때그때 다른 것"이 된다.
  **하나의 원리가 모든 상황에 답을 내게 하라.** 원리가 답 못 내는 자리 — 거기가 전복 지점이다.

### Q3. 이 도메인에서 AI는 어떻게 도망가는가? ★ 가장 중요
→ **연산자**가 된다.
- 도망 방식 하나마다 기호를 하나씩.
- **도메인마다 도망 방식이 다르다. 미리 주어진 연산자는 없다.**

### Q4. 이 도메인에서 "모른다"는 어떤 모양인가?
→ **구멍**이 된다.
- **작가의 구멍**(아직 안 정함)과 **행위자의 무지**(세계엔 정해져 있음)를 구별하라.
  섞으면 안 된다. 앞은 위반이고 뒤는 자원이다.

### Q5. 이 도메인에서 "무너진다"는 무엇인가?
→ **전복 장치**가 된다.
- **없으면 아무도 변하지 않는다.** 변화가 없으면 이야기도 논증도 없다.
- 무엇을 **알면** 이 존재가 자기 원칙을 버리는가.
- 전복은 **앎에서만** 와야 한다. 설득·감동·시간 경과로 변하면 그건 공짜다.

### Q6. 이 도메인에서 "좋다"는 무엇인가?
→ **통과 조건**이 된다.
- 없으면 평균이 통과한다.
- **결과가 아니라 과정에 걸어라.** 결과만 채점하면 연출이 되고 과정이 가짜가 된다.

### Q7. 이 도메인에서 "굴린다"는 무엇인가?
→ **시뮬레이션**이 된다.
- 무엇이 상태이고, 무엇이 **한 스텝**이고, 무엇이 종료인가.
- **한 스텝을 시간 단위로 정의하지 마라.** 그러면 시간순이 되고, 시간순은 산문이다.
  한 스텝은 **무언가가 결정되고 상태가 바뀌는 것**이다.

### Q8. 이 도메인에서 무엇이 key이고 무엇이 text인가? (v0.2 신규)
→ **코드화의 경계**가 된다. (6절)
- 무엇을 AI가 조작하고, 무엇을 사람이 읽는가.
- text가 필요한 자리는 어디인가. (판단이 필요한 곳만)

## 7-B. 생성 규칙 ★ — 도메인 코산 정의가 반드시 포함해야 할 것

**Q1~Q8 의 답만 적으면 안 된다.**
그러면 그 문서를 읽는 AI는 **코산이 무엇인지 모르는 채로** 문법만 흉내낸다.
문법만 있으면 AI는 "코드처럼 생긴 산문"을 만들고, 그게 통과된다.

**생성되는 도메인 코산 정의는 반드시 아래 두 절을 맨 앞에 포함한다.**
요약하지 마라. 빼먹지 마라. **틀은 그대로 두고 <?> 자리만 도메인에 맞게 채워라.**

### 필수 절 ① — 코산이란 무엇인가 (자기 정의)

```markdown
## 코산이란 무엇인가

> 코산 = 생각을 코드 형태로 적은 것. 실행기는 사람 또는 AI. 코드 자체가 결과물.

- 프로그래밍 언어가 아니다. 컴파일러가 없다. 문법이 정확할 필요는 없다.
  단, **코드처럼 보여야 한다.** 안 그러면 산문으로 돌아간다.
- 결과물(<?도메인 산출물: 소설/합의문/…>)은 코산에서 **나중에 렌더링**한다.
  코산이 소스이고, 산출물은 빌드 결과다.
- **코산 = 소스 = 기억 = 결과물.** 요약하지 않는다. 요약은 손실이다.

### 왜 이렇게 하는가

AI는 산문에서 얕아진다.
- **수식어는 회피다.** 구조를 안 정해도 분량이 나오는 유일한 방법이다.
  리스크 없이 분량이 나오므로 AI에게 이건 최적 전략이다.
- **평균은 제약이 없을 때 나오는 답이다.** 조건이 없으면 가장 흔한 것이 나온다.
- **산문은 고칠 수 없다.** 이미 쓴 텍스트가 앵커가 되어 비슷한 것만 다시 나온다.

코산은 이것을 **금지로 막지 않는다. 불가능하게 만든다.**
- 꾸미지 말라고 시키지 않는다 → 꾸밀 칸이 없다
- 평균을 금지하지 않는다 → 평균이 통과 못 하는 관문을 세운다
- 기억력을 늘리지 않는다 → 기억할 필요를 없앤다 (상태가 곧 기억)

### 검사자는 없다

**상태(입력) → 코산 → 상태(출력). 이것이 그대로 검사다.**
- 산문이 섞이면 **참조가 안 된다.** 다음 스텝이 그걸 못 읽는다.
- 묘사를 넣으면 **아무것도 안 바뀐다.** 스스로 사라진다.
- 구조가 비면 **STOP** 난다.

### 이 도구의 핵심은 빈자리를 찾는 것이다

산문은 빈자리가 안 보인다. 문장이 있으면 뭔가 있는 것처럼 읽힌다.
코산은 **"여기에 함수가 없다", "이 값이 ?? 다"** 를 정확히 짚는다.
**같은 자리를 반복해서 가리키면, 거기가 급소다.**
```

### 필수 절 ② — 이 문서를 읽는 AI에게 (사용법 / 금지)

```markdown
## 이 문서를 읽는 AI에게 ★ 먼저 읽어라

**너는 <?도메인 산출물>을 쓰지 않는다. 코산을 만들고 굴린다.**

가장 저항이 적은 길은 산문을 쓰는 것이다. 그럴듯하게 나오고, 아무도 안 막는다.
**그 길로 가면 이 전체가 무의미해진다.**

### 절대 금지

✗ **산문을 쓰지 마라**
    코산 파일에 문장을 쓰면 위반이다.
    <?이 도메인에서 산문이란: 예 — 소설이면 묘사, 토론이면 인상·수사>
    묘사는 나중에 렌더링에서 붙인다.

✗ **?? 를 채우지 마라**
    씨앗에 없는 것은 ?? 로 남겨라.
    그럴듯하게 채우고 싶은 충동이 들 것이다. 그게 평균이다.
    ?? 는 결함이 아니라 다음 작업의 좌표다.

✗ **창작하지 마라 (시뮬레이션 중)**
    코산에 없는 것을 지어내지 마라.
    막히면 STOP 하고 보고하라. 우회하지 마라.
    ★ STOP 이 성과다. 멈춘 자리가 다음에 쓸 코드가 있어야 할 자리다.

✗ **"그럴듯해서" 추가하지 마라**
    <?이 도메인의 실제 위반 사례를 적어라.
     예(소설): 고블린이 지면 항복한다고 지어냈다. 씨앗에도 코산에도 없었다.
     "이야기가 되니까" 넣었다. 이것이 창작이다. 최악의 위반이다.>
    창작하면 버그가 숨고, "잘 굴러가네"라는 거짓 신호가 나온다.

✗ **코드처럼 생겼다고 통과가 아니다**
    영문 스네이크케이스로 썼어도, 아무도 참조하지 않는 필드는 묘사다.
    예: torches(flickering), mud_ground — Δ 도 없고 어떤 함수도 안 읽는다.
    **"코드처럼 보이면 통과"가 아니라 "참조되면 통과"다.**

### 절차

1. 이 문서(문법)를 읽는다
2. 씨앗을 받는다
3. 코산을 만든다 — 씨앗에 있는 것만. 없는 것은 ??
4. 초기 상태를 만든다
5. 굴린다 — 창작 금지. 없으면 STOP.
6. STOP 하면 보고한다: 무엇이 없어서 멈췄는가 / 어디를 채워야 하는가

### 사람이 하는 일 / AI가 하는 일

사람 — 씨앗, 통과조건, 요청, 판단, 판 고르기
       ★ **방향을 정하는 값은 사람이 정한다**
AI   — 코산 작성, 굴리기, 빈자리 보고, 후보 제시
       ★ 갈림이 작은 자리는 채워도 된다 (틀려도 한 줄이니까)
       ★ 갈림이 큰 자리는 **후보만 주고 멈춘다**

**기준: 이 채움이 방향을 정하는가. 정하면 멈춘다.**
**후보를 줄 때는 반드시 "또는 직접:" 을 열어둔다.**
AI가 만든 선택지 안에 사람을 가두면, 나오는 것은 AI의 결과물이다.
```

### ★★ 금지 정본 — 그대로 복사할 것

**생성하는 모든 도메인 정의의 맨 앞에 아래 블록을 그대로 넣는다.**

```
★ 재서술하지 마라. 요약하지 마라. 순서를 바꾸지 마라. 그대로 복사하라.
  풀어 쓰면 녹는다. 녹으면 지켜지지 않는다.
```

그래서 **짧게** 만들고 **베끼게** 만든다. 길면 요약되고, 요약되면 사라진다.

```

✗ 참조되지 않는 필드       ★ 코드처럼 생겨도 아무도 안 읽으면 묘사다

✗ 분기 하나만             그건 실행 결과 하나를 적은 것
✗ 과정 없는 매핑          인과가 없으면 판단이 안 된다
✗ 꾸밈, 묘사              칸이 없다. 렌더링에서 붙인다.
✗ 시간순 나열             소스에 오면 산문이 된다. trace에만 허용.
✗ 선언 안 한 상태 변경     창작이다. 반려.
✗ 구멍을 몰래 채우는 것     최악의 위반
```

**가장 흔한 실패 셋:**

1. **시간순으로 적어 산문의 연속이 되는 것.**
   진짜 코드는 시간 순서로 놓이지 않는다. 함수는 호출될 때 실행된다.
2. **껍데기만 기호고 값이 문장인 것.** ← v0.1이 실제로 이렇게 됐다.
3. **영문으로 썼는데 아무도 참조 안 하는 것.** ← v0.2로 생성해도 이건 샜다.
   `torches(flickering)`, `mud_ground` — 코드 옷을 입은 묘사다.

## 9. 문법에 대하여

**기호도, 키워드도, 표기도 도메인이 정한다. 메타는 정하지 않는다.**

- 컴파일러가 없다. 문법은 **느슨해도 되고, 자라도 되고, 틀려도 된다.**
- 문법에 없는 걸 써도 안 터진다. 필요하면 그 자리에서 연산자를 만들어 쓴다.

**단, 구분하라:**

```
느슨해도 되는 것    기호 선택, 키워드 이름, 표기의 세부
빡세야 하는 것      규율 (8절) + 코드화 (6절)
```

**컴파일러 자리에 검사자를 둔다. 문법이 아니라 규율을 검사한다.**

**문법을 먼저 정하지 마라.** 막히는 자리에서 개념이 나온다.
**막힘이 문법을 낳는다. 문법이 표현을 낳지 않는다.**

## 10. 실행 구조

### 코산은 프로그램처럼 폴더/파일 형식으로 작성한다 ★

**코산은 코드다. 그러므로 코드처럼 다룬다.**

- **확장자는 `.cosan` 으로만.** 다른 확장자를 쓰지 않는다.
  (정의 문서만 `.md` 또는 `.cosan` 중 택일)
- **★ 메모리에서 작업하지 않는다. 항상 파일로 기록한다.**
  대화 안에서만 만들고 파일로 남기지 않으면 그것은 코산이 아니다.
  상태를 밖에 두는 것이 이 방법론의 근간이고, 파일이 없으면
  되돌릴 수 있음(diff·이전 판·재실행)도, 굴리기가 검사인 것도,
  다음 세션이 이어받는 것도 전부 성립하지 않는다.
  → 만들었으면 그 자리에서 쓴다. 대화 출력은 보고이지 저장이 아니다.
  → 파일에 못 쓰면 STOP. 메모리에서 계속하지 않는다.
- 한 덩어리 파일이 아니라 **폴더로 분할**한다. 실(thread)별 / 종류별로 나눈다.
- 작업 시 **필요한 파일만 연다.** 전체를 읽지 않는다.
  → 이것이 국소성이다. 규율이 아니라 구조로 강제된다.
- 어디에 무엇이 있는지는 **폴더 구조와 파일명**이 알려준다. (사람이 코딩할 때와 같다)
- 찾을 때는 grep. 텍스트 파일이므로 검색이 공짜다.
- 커져도 버틴다. 코드를 고칠 때 전체를 안 읽듯, 참조하는 부분만 본다.

```
<도메인 예시: 소설>
<작품>/
├── COSAN.md 또는 COSAN.cosan     이 작품의 문법 (정의)
├── <종류별 폴더>/*.cosan          소스.  분할됨.
├── INDEX.cosan                   순서의 유일한 정의 (있는 도메인의 경우)
└── traces/                       굴린 결과.  버려도 됨.
    └── run_NN/  s000.cosan ...    상태 목록 = 결과물
```

**코산은 그냥 git 저장소다.**
diff / branch("만약에") / commit(작업 단위) / blame(정의의 출처 추적) 이 전부 공짜로 따라온다.

### 파일 셋 (개념)

```
<도메인>.cosan    소스. 결정과 규칙. 시간순 아님. 계속 커진다.
state             지금 값. 기억. 작다. 배턴. (trace 의 마지막 상태)
trace             시간순 상태 목록 = 결과물 그 자체
```

**trace는 부산물이 아니다. 굴리는 과정 자체가 결과물이다.**
답이 아니라 **과정**이 스토리이고 토론이다.

### 한 스텝

```
1. state.now 확인
2. 조건 맞는 함수 탐색
3. 없으면      → STOP: "아무것도 발동 안 함"       ★ 버그
   여럿이면     → 갈라짐. 각각 굴린다.
4. 함수 실행: 입력 → 충돌 → 과정 → 선택 → 대가
5. 분기에 없는 입력 → STOP: "미정의 입력"          ★ 버그
6. 상태 갱신 — 함수가 선언한 것만                  ★ 창작 방지
7. 전복 조건 검사 → 발동하면 원칙 교체 + 대가 지불
8. 규율/검사자 통과? → 위반이면 STOP               ★ 버그
9. 반복
```

**STOP ≠ 종료. STOP은 버그다. 그리고 버그가 성과다.**

### 두 가지 쓰임

```
① 스텝 검증    상태1 → 코산 → 상태2
               한 스텝만. "이게 맞나?"
               → 코드를 고치는 게 목적. 빠르고 값싸다. 반복한다.
               → 여기서 전복 장치가 생긴다.
                  "이건 아닌데"라고 느끼는 순간이 그 자리다.
               → 전복이 생기면 근거를 역산하고, 앞을 소급 검사한다.

② 전체 실행    상태1 → ... → 상태N
               끝까지. "이 판이 좋나?"
               → 판단하는 게 목적. 결과물을 얻는다.
```

**①로 다지고 ②로 본다. ②에서 터지면 그 지점으로 내려가 ①을 한다.**

**②는 반드시 여러 번 굴린다.**

```
sim A → 결말 X
sim B → 결말 X     ⚠
sim C → 결말 X     ⚠  이 코산은 한 가지밖에 못 낳는다 = 평균
```

**같은 지점에서 갈라 굴려 결과가 다 같으면, 그 분기는 가짜다.**
이것이 평균을 **기계적으로 검출**하는 방법이다.

## 11. 전체 흐름

```
[사람]  씨앗 + 통과조건               ← 판단. 이것만 한다.
   ↓
[AI]   코산 v0 생성  (구멍 채워도 된다. 평균이어도 된다. 고치면 되니까.)
   ↓
[AI]   ① 스텝 검증 — 창작 금지. 없으면 STOP.
   ↓
[사람] "이건 아닌데"  →  전복 장치 생성  →  근거 역산  →  소급 검사
   ↓
[AI]   같은 상태 다시 넣음 → 다른 출력            ← 재실행
   ↓  (반복)
   ↓
[AI]   ② 전체 실행 → trace = 결과물
   ↓
[검사] 통과조건 만족? → No면 그 지점으로 내려가 ①
   ↓
[AI]   여러 판 굴리기 → 여러 trace
   ↓
[사람] 판 고르기                       ← ★ 평균 탈출
   ↓
[AI]   렌더링 (원하면) — 조각 단위. 작은 모델로도 가능.
                        Δ와 대가는 못 바꾼다. 바꾸면 새 코산이지 렌더링이 아니다.
```

**사람은 씨앗과 통과조건만 주고, 마지막에 구조와 판을 읽는다.**
중간의 테스트/디버그 루프를 AI가 대신 돈다 — 원래 사람이 하던 부분.

## 12. 사용 방식

**사람은 코산을 직접 안 본다.** 바이브코딩과 같다.

```
"왜 여기서 이렇게 했지?"     →  AI가 코산 읽고 설명한다 (계산을 보여준다)
"여기선 이래야 해"          →  AI가 코산을 고친다
"이건 이런 것이다"          →  AI가 구조에 반영 + 모순 검출
```

코산 파일은 접혀 있다. 여는 건 — **막혔을 때 / 조망할 때 / 디버깅할 때.**

### 인터페이스가 산문과 같은데 왜 코산인가

```
산문:   사람 ↔ AI ↔ [산문]
코산:   사람 ↔ AI ↔ [코산]
```

**사람 눈엔 똑같지만 AI가 붙잡고 있는 게 다르다.**

- 산문 → AI가 전부를 기억해야 함 → 못 함 → 요약 → 샌다
- 코산 → AI가 한 줄만 보면 됨 → 안 샌다

**그리고 대화가 검증된다.** 새 요구가 기존 구조와 충돌하면 코산은 **충돌이라고 말한다.**
산문은 뭐든 그럴듯하게 이어 붙인다 — 그래서 물러진다.

## 13. 도메인 코산 목록

```
[생성됨]   소설용 코산 v0.1   — 메타 v0.1로 생성. 값이 문장이라 산문 회귀 위험. v0.2로 재생성 필요.
[예정]     소설용 코산 v0.2   — 코드화 강제 적용
[예정]     토론용 코산
```

**메타는 두 도메인 이상 만들어봐야 다듬어진다.**
하나로는 무엇이 도메인 특수고 무엇이 공통인지 구분되지 않는다.
