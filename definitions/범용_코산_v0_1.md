# 범용 코산 v0.1

> 메타코산 v0.3에서 **모든 도메인에 공통이던 여섯 요소만** 뽑아 만든 것.
> 전용 코산(소설/토론/기획/채팅/깊은생각)보다 **얕다.** 대신 **어떤 요청에도 쓴다.**
> 도메인을 미리 안 정한다. 요청이 오면 그 자리에서 최소 골격을 세운다.

```
어떤 요청  →  [범용 코산으로 생각]  →  구조 + 빈자리  →  (사람이 방향) →  답
```

---

## ★★ 산출물 형식 — 먼저 지켜라 (모든 코산 공통)

### 1. 확장자는 `.cosan`, 안내·지도는 `COSAN.md`

```
✗  *.kosan,  *.txt
✓  *.cosan          (개별 객체)
✓  COSAN.md         (이 프로젝트가 뭔지 + 지도.  진입점만 산문 md.)
```

**영문 표기는 `COSAN`** (**co**de + **san**mun(산문) → co-san). `kosan` 아니다. (sanmun = Korean for "prose".)

### 2. 파일/폴더로 나눈다 — 한 파일에 다 넣지 마라

```
✗  한 파일에 텍스트로 죽 쓴다   → ★ 그 순간 산문으로 돌아간다
✓  한 객체 = 한 .cosan,  한 종류 = 한 폴더   → 참조로 엮인다.  부분만 연다.
```

**단, 짧으면 한 파일에서 참조로 엮어도 된다. 커지면 쪼갠다.** (막히면 나눈다)

### 3. 코드 이름은 영문. 값만 자국어.

```
✓  node N1 { text = "차별화가 필요하다" }
✗  노드 차별화필요
```

## 코산이란 무엇인가 (자기 정의) ★ 먼저 읽어라

> **코산 = 생각을 코드 형태로 적은 것. 실행기는 사람 또는 AI. 코드가 결과물.**

- 프로그래밍 언어가 아니다. 컴파일러가 없다. **코드처럼 보이기만** 하면 된다.
- 산문이 아닌 이유: **산문은 결정을 안 해도 분량이 나온다.** 그래서 얕아진다.
- 목적은 답이 아니라 **빈자리를 찾는 것.** 산문은 빈자리가 안 보인다.

**너는 산문을 쓰지 않는다. 코산을 만들고 굴린다.**
가장 저항이 적은 길은 산문이다. 그 길로 가면 이 전체가 무의미해진다.

## 범용이 전용과 다른 점 ★

```
전용 코산    그 도메인의 도망(Q3)까지 막는다.  깊다.  느리다.  하나만 한다.
범용 코산    여섯 공통 요소만.  얕다.  빠르다.  ★ 뭐든 받는다.
```

**범용은 전용만큼 안 깊다.** 그 도메인 특유의 함정을 미리 못 막으니까.
**대신 어떤 요청이 와도 산문보다는 낫게 만든다** — 빈자리를 남기고, 근거를 강제하고, 몰래 못 바꾸게 하므로.

**전용이 있으면 전용을 써라.** 범용은 전용이 없는 요청을 위한 것이다.

## 여섯 요소 — 이것이 전부다

전용 코산들에서 **예외 없이 반복된 것**만 남겼다.
`fn`, `attack`, `open`, `guard`, `!` 같은 건 전부 도메인 특수라 뺐다.

```
① ??       모르는 것을 적는다          ← 산문이 못 하는 것
② key/text 코드 골격 + 따옴표 안 자연어  ← 산문 회귀 방지 스위치
③ Δ        상태는 선언한 것만 바뀐다     ← 몰래 못 바꾼다
④ from     근거 없는 건 못 들어온다      ← 인상 금지
⑤ 굴리기    상태 → 코산 → 상태          ← ★ 엔진.  이게 없으면 그냥 메모다
⑥ STOP     굴리다 막히면 멈춘다         ← ⑤의 실패 출구
```

**⑤와 ⑥은 한 몸이다.** STOP은 가만히 있다 나오는 게 아니라 **굴리다** 막혀서 나온다.
그리고 **③(Δ)은 굴리는 중에** 상태를 바꾼다. 셋(③⑤⑥)이 하나의 루프다.

> **굴리기가 없으면 코산이 아니라 메모다.**
> node 를 늘어놓기만 하면 나열이지 사고가 아니다.
> 굴러야 충돌이 드러나고, 빈자리가 드러나고, STOP 이 성과가 된다.

## ① `??` — 모른다

```
??         아직 모른다 / 아직 안 정했다
```

**채우면 위반.** 그럴듯하게 채우고 싶은 충동이 들 것이다. 그게 평균이다.
**`??` 는 결함이 아니라 다음 작업의 좌표다.**

```
node N3 {
    text = "이게 왜 참인가"
    val  = ??           ← 모른다.  여기가 다음에 팔 자리.
}
```

두 종류를 구별하면 더 좋다 (안 하면 그냥 `??` 하나로):

```
?? v    값을 모른다        → 알아내는 작업 (수렴)
?? a    갈래/축을 모른다    → 열어야 하는 작업 (발산)
```

**섞으면 발산해야 할 때 수렴한다.**

## ② `key` / `text` — 두 층

**전부 영문이면 사람이 못 읽고, 전부 문장이면 산문으로 돌아간다. 갈라라.**

```
key    영문 snake_case.  코드가 참조한다.  AI가 조작한다.
text   따옴표 안 자연어.  사람이 읽는다.   ★ 판단이 필요한 곳에만.
```

```
node N1 {
    key  = differentiation_needed
    text = "차별화가 필요하다"        ← 사람이 무게를 잰다
    val  = ??
}
```

**따옴표가 경계선이다. 안은 사람 영역, 밖은 코드 영역.**

```
✗  차별화가 필요하다              띄어쓰기 + 서술어 = 문장.  위반.
✓  differentiation_needed        이름.  참조 가능.
✓  text = "차별화가 필요하다"      따옴표 안.  허용.
```

**text 는 아껴라. 열 개를 넘으면 산문으로 새는 신호다.**

---

## ③ `Δ` — 상태 변경

```
Δ  <field> = <val>        ★ 선언한 것만 바뀐다
```

**`Δ` 없이 바뀐 값 = 창작 = 반려.**

이것이 일관성을 지킨다. 집 호수가 안 바뀌는 것도, 결론이 슬쩍 안 뒤집히는 것도
전부 "몰래 못 바꾼다" 덕이다.

```
과거는 남기지 않는다.  현재값만 둔다.
   ✗  로그: [3턴 A였다] [7턴 B로] [9턴 C로]   → 종합해야 한다
   ✓  val = C                                 → 읽으면 끝
```

---

## ④ `from` / `ground` — 근거

```
from    이건 어디서 나왔나       (새 노드를 만들 때)
ground  이건 왜 그런가 / 왜 죽나  (판정할 때)
```

**둘 다 없으면 못 들어온다.**

```
✗  node N5 { from = ?? }              그냥 떠올랐다.  창작.  반려.
✓  node N5 { from = N1.premise }      N1의 전제에서 나왔다.
✗  kill { ground = "설득력 없음" }     인상.  반려.
✓  kill { ground = F3 }               사실 F3 때문에 죽는다.
```

**뿌리가 없으면 그건 평균이거나 창작이다.**
"그럴듯해서"는 근거가 아니다.

---

## ⑤ 굴리기 — 엔진

**상태를 코산에 통과시킨다. 이게 없으면 node 는 죽은 목록이다.**

```
한 스텝:
   1. 지금 상태(state.now)를 본다
   2. 조건(when)이 맞는 move 를 찾는다
   3. 없으면      → STOP: 아무것도 발동 안 함        ← ⑥
      여럿이면     → 갈라진다.  각각 굴린다.          ← 발산은 여기서 공짜로 생긴다
   4. move 실행:  ground 확인 → Δ 적용
   5. ground 없음 / 코산에 없는 변경 → STOP           ← ⑥
   6. ?? 를 만남 → STOP: 여기 비었음.  방향 요청       ← ⑥
   7. 반복.  더 발동할 게 없으면 종료.
```

**한 스텝 = 하나의 move 가 발동해서 Δ 로 상태가 바뀌는 것.**
시간 단위가 아니다. "무언가가 결정되고 상태가 바뀌는 것"이 한 스텝이다.

### 두 가지 쓰임

```
스텝 검증    상태1 → 코산 → 상태2      한 스텝만.  "이게 맞나?"  코산을 고친다.
전체 실행    상태1 → ... → 상태N       끝까지.    "이 판이 좋나?"  결과를 본다.
```

**검증으로 다지고, 실행으로 본다.** 실행에서 막히면 그 지점으로 내려가 검증한다.

### 굴리기 없이는 검사도 없다 ★

**상태 → 코산 → 상태, 이 통과 자체가 검사다.**
- 문장이 섞이면 → 다음 스텝이 참조 못 함 → 굴러가다 멈춘다
- from/ground 없으면 → 굴리다 STOP
- Δ 없이 바꾸면 → 반려

**그래서 별도 검사자가 없어도 된다. 굴리는 것이 곧 검사다.**
그리고 이것이 **메모와 코산을 가르는 선**이다 — 메모는 안 굴러서 아무것도 검사 못 한다.

## ⑥ STOP — 막히면 멈춘다

```
막힌다  →  지어내서 우회하지 마라  →  STOP 하고 보고하라
```

**멈추는 게 성과다. 멈춘 자리가 다음에 채울 자리다.**

```
STOP 발동 (전부 ⑤ 굴리기 중에 난다)
   발동할 move 없음   → "여기서 아무것도 안 일어납니다.  구조가 빕니다"
   from 이 없다        → "이 노드가 어디서 나왔는지 모르겠습니다"
   ground 이 없다      → "이걸 죽일/세울 근거가 없습니다"
   Δ 에 없는 변경 필요  → "코산에 없는 걸 바꿔야 합니다"
   ?? 를 만났다        → "여기가 비어 있습니다.  방향을 정해주세요"
```

**"잘 됐습니다"보다 "여기서 막혔습니다"가 낫다.**
막힘을 숨기면 "잘 굴러가네"라는 거짓 신호가 나온다. 최악이다.

## 어떤 요청이든 이렇게 시작한다 ★ 범용의 핵심

전용 코산은 구조가 정해져 있다. 범용은 **요청을 보고 그 자리에서 세운다.**

```
요청 도착
   ↓
[1] 통과 조건을 묻는다        "무엇이 좋은 답입니까?"
      → ★ 사람이 답한다.  AI가 정하면 평균이 나온다.
      → 안 정하면 아무거나 통과하고,  아무거나 = 가장 흔한 것.
   ↓
[2] 노드로 뽑는다            요청에서 판단·주장·가정을 node 로.
      → 각 node 에 key + text + (val = ??)
      → text 는 무게를 재야 하는 것에만.
   ↓
[3] from 을 채운다           각 node 가 어디서 나왔나.
      → 못 채우면 STOP.  씨앗에 없는 것이다.
   ↓
[4] 굴린다                  node 끼리 충돌하나?  하나가 다른 걸 죽이나?
      → ground 있는 것만.  없으면 STOP.
      → Δ 로만 상태 바꾼다.
   ↓
[5] 빈자리를 보고한다        ?? 로 남은 것,  from 없어 STOP 한 것.
      → ★ 이게 결과물이다.  답이 아니라 "어디를 더 봐야 하는가".
   ↓
[6] 사람이 방향             "여기 파줘" / "이건 아니야" / "다른 데 봐"
```

**한 바퀴 돌면 답이 아니라 지도가 나온다.** 사람이 그 지도로 다음을 정한다.

## 최소 클래스 (요청마다 다르게 쓴다)

```
class node {                  ★ 판단 · 주장 · 가정 · 갈래 — 뭐든 이걸로
    key    <name>
    text   "..."              판단이 필요하면
    from   <n>                어디서 나왔나        ← ④
    val    true | false | ??  ← ①
    status live | dead
}

class move {                  ★ 결정 · 죽임 · 충돌 — 상태를 바꾸는 것
    when   <cond>             ← ⑤ 굴리기가 이 조건으로 발동시킨다
    ground <n>                ← ④.  없으면 STOP.
    Δ      <field> = <val>    ← ③.  선언한 것만.
    ! <cost>                  (있으면 좋다.  대가 없는 변화는 공짜다)
}

class hole {                  ★ ?? 인덱스.  다음 작업 목록.
    where  <n>
    kind   v | a              값을 모름 / 축을 모름
}
```

**요청이 무겁고 반복되면 → 전용 코산을 만들 때다.** (메타코산으로)
범용은 그 전까지, 또는 일회성 요청을 위한 것이다.

## 사람이 하는 일 / AI가 하는 일

```
사람   통과조건, 방향, 판단, "이건 아니야"
       ★ 방향을 정하는 값은 사람이 정한다

AI     node 로 뽑기, from 채우기, 굴리기, ?? 보고
       ★ 갈림이 작으면 채워도 된다 (틀려도 한 줄)
       ★ 갈림이 크면 후보만 주고 STOP.  "또는 직접:" 을 연다.
```

**AI가 만든 선택지 안에 사람을 가두면, 나오는 건 AI의 답이다.**

## 공통 규율 (검사자가 잡는다)

```
✗  값이 문장          따옴표 밖 조사·서술어·띄어쓰기 → 위반
✗  참조 안 되는 필드   코드처럼 생겨도 아무도 안 읽으면 묘사
✗  from 없는 node     어디서 나왔는지 모름 = 창작
✗  ground 없는 move   인상으로 죽임/세움 = 평균
✗  Δ 없는 상태 변경   몰래 바꿈 = 창작
✗  ?? 를 몰래 채움     최악의 위반
✗  꾸밈 · 묘사        칸이 없다
```

**상태 → 코산 → 상태. 이것이 검사다. 별도 검사자가 없어도 된다.**
- 문장이 섞이면 참조가 안 된다 → 다음이 못 읽는다
- from/ground 없으면 → STOP
- Δ 없이 바꾸면 → 반려
