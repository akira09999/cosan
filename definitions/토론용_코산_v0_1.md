
## ★★ 산출물 형식 — 이것을 먼저 지켜라 (모든 코산 공통)

**이 세 가지는 도메인과 무관하게 고정이다. 어기면 코산이 아니다.**

### 1. 확장자는 `.cosan` 이다

```
✗  KOSAN.md,  *.kosan,  *.md,  *.txt
✓  *.cosan
```

**영문 표기는 `COSAN` 이다.** (**co**de + **san**mun(산문) → co-san / 코산 — 산문이라는 매체를 코딩화한다는 뜻. sanmun = Korean for "prose".) `kosan` 이 아니다.
`kosan` 이 아니다. 개별 코산 객체는 `.cosan` 파일로,
이 프로젝트의 문법·구조·지도는 최상위 `COSAN.md` 에 둔다.

### 2. 코산은 파일/폴더 구조로 만든다 ★★ 한 파일에 다 넣지 마라

**코산은 "코딩된 산문"이다. 코드처럼 ★ 파일과 폴더로 나눈다.**

```
✗  전부 한 파일(.md, .txt)에 텍스트로 쓴다
    → ★ 그 순간 산문으로 돌아간다.  이 방법의 존재 이유가 사라진다.
    → 한 파일이면 참조가 안 되고,  부분만 열 수 없고,  스케일이 안 된다.

✓  객체마다 파일 하나.  종류마다 폴더 하나.
    → 코드베이스처럼.
    → 필요한 파일만 연다.  나머지는 안 읽는다.  (작은 모델·긴 작업에 결정적)
```

**한 객체 = 한 `.cosan` 파일. 한 종류 = 한 폴더.**
파일 안에서 다른 객체는 **코드 이름으로 참조**한다 (예: `home = W_APT_601`).
참조가 관계를 붙들기 때문에, 파일을 나눠도 안 흩어진다.

### 3. 코드 이름은 영문. 값만 자국어.

```
✓  char C_AJUMMA { name = "박순자" }      ← 손잡이는 영문,  값은 따옴표 안 자국어
✗  캐릭터 아줌마 { 이름 = 박순자 }
```

**영문 코드 이름이 유일한 불변(주소)이다.** 값(이름 등)은 바뀌어도 참조가 안 끊긴다.

## 0. 이 도메인의 대전제

```
토론 = 주장이 공격받고 살아남거나 죽는 연쇄
목적 = 이기는 것도, 합의도 아니다.  ★ 생각의 완전함을 아는 것.
결론 = 렌더링 산출물.  소스에 칸이 없다.
```

**합의는 평균이다.** 여러 관점을 하나로 합치는 연산이 곧 평균화다.
그래서 이 코산은 **수렴하지 않는다.** 살아남은 주장들과 뚫린 구멍들을 그대로 내놓는다.
고르는 것은 사람이다.

**그리고 토론의 산출물은 결론이 아니라 trace다.**
어느 주장이 어느 공격에 어떻게 답했고, 어디서 못 답했는지 — 그 과정이 결과물이다.

### 왜 코산이 필요한가 (이 도메인 고유의 병)

에이전트를 여럿 두고 토론시키면 이렇게 된다:

```
에이전트1이 의견 A를 낸다
   ↓
에이전트2는 두 가지만 한다:  A에 동조 / A에 반대
   ↓
에이전트3은 A와 ¬A 사이에서 논다
   ↓
논의가 주제가 아니라 의견을 중심으로 돈다
```

**앞 발언이 컨텍스트에 들어가는 순간, 과제가 바뀐다.**
"이 문제를 생각하라"가 "이 주장에 반응하라"로 치환된다.
그리고 반대조차 첫 의견이 깔아놓은 좌표계 위에서 나온다.

**그러므로 이 코산의 제1 임무는 발언 이력을 상태에서 제거하는 것이다.**
상태는 발언록이 아니라 **주장 그래프**다.

## Q1. 결정이란 무엇인가 → `fn`

**결정 = 공격받은 논자가 방어 · 수정 · 철회 중 하나를 고르는 것.**

```
fn <n>(<inputs>) {
    when    <state_condition>
    clash   <claim> >< <attack>          ★ 공격 없으면 결정이 아니다
    proc    <n> -> <n> -> <n>             ★ 이름으로.  문장 금지.
    branch  <input_val> => defend  ! <cost>
            <input_val> => amend   ! <cost>
            <input_val> => retract ! <cost>
            _           => STOP:undefined_input
    Δ       <state.field> = <val>
}
```

### 세 가지 선택과 그 대가 ★

```
defend    근거를 댄다        ! 근거가 없으면 못 한다.  ← 이게 제약이다
                              새 근거를 대면 그 근거가 새 공격 대상이 된다
amend     주장을 좁힌다       ! scope ↓                ← 공짜처럼 보이지만 아니다
                              범위를 잃는다.  좁힌 만큼 주장이 약해진다
retract   철회한다           ! 이 주장에 의존하던 것들이 전부 흔들린다
                              → cascade 검사 발동
```

**`evade` 는 없다.** 그게 이 도메인의 도망이고, 연산자를 안 만듦으로써 불가능하게 만든다.
(Q3 참조)

- **branch 2개 이상.** 하나면 실행 결과지 함수가 아니다.
- **`!` cost 없는 branch는 위반.** 대가 없는 방어는 결정이 아니다.
- `defend` 는 근거를 소비한다. 근거 없이 defend = STOP.

## Q1'. 공격이란 무엇인가 → `attack` ★

```
attack A_<n> {
    target   <claim_id> | <premise_id>
    type     ground | premise | scope | consequence | counterexample
    ground   <근거>                       ← 공격도 근거가 있어야 한다
    text     "..."                        ← 한 문장.  사람이 무게를 잰다.
    hooks    <앞 attack/claim>            ← 무엇을 무나 (선택)
    leaves   [ ?? <미정> ]                ★ 다음이 물 고리
}
```

### 공격 타입 (이 도메인의 압력)

```
ground          근거가 그 결론을 지지하지 않는다
premise         숨은 전제가 거짓이다
scope           그 주장이 커버 못 하는 경우가 있다
consequence     그 주장을 받아들이면 X도 받아들여야 한다.  그런데 X는 거짓이다
counterexample  반례.  ★ 가장 강하다.  하나면 족하다.
```

**공격은 세계가 준다.** 논자가 지어내는 게 아니다.
반례는 논자와 무관하게 존재한다 — 사실이니까.

```
✓  세계가 반례를 준다        "1998년에 정반대 사례가 있다"
✗  세계가 결론을 준다        "따라서 A가 옳다"           ← 우연.  금지.
```

**공격만 준다. 판정은 안 준다.**

### 공격은 순서에 안 묶인다 ★

`hooks` 만 있고 순서가 없다.
그래서 **나중에 발견한 공격을 앞에 끼울 수 있다.**

```
C1  →  [ 공격 5개 ]  →  C7
           ↑
     나중에 여기 하나 더 끼워도
     앞뒤를 안 건드린다.
     뒤의 fn 들이 상태를 참조하므로 → 뒤가 자동으로 달라진다.
```

**산문 토론:** 3번 발언과 4번 발언 사이에 뭘 넣으려면 둘 다 다시 써야 한다.
**코산:** hook 에 걸고 재실행. 뒤가 알아서 달라진다.

## Q2. 지속되는 것은 무엇인가 → `class`

```
class claim {
    text      "..."                  ★ 한 문장.  주장 그 자체.
    scope     [ <적용 범위> ]         ★ 없으면 공격 못 한다.  ← 소설의 principle.scope 와 같다
    ground    [ <근거 id>... ]        무엇이 이걸 받치나
    depends   [ <premise id>... ]     숨은 전제.  ★ 안 적으면 premise 공격을 못 받는다
    status    live | amended | dead
}

class premise {
    text      "..."                  ★ 논자가 안 적었지만 필요한 것
    val       true | false | ??      ← ?? 가 고민이다
    hidden    true | false           ★ 논자가 자각하고 있나
}

class arguer {
    position     <claim_id>
    commitments  [ <claim_id>... ]    ★ 이미 인정한 것.  나중에 자기 발목을 잡는다
    knows        [ <fact_key>... ]
    ★ 발언 이력을 두지 않는다.  두는 순간 앵커가 생긴다.
}

class world {
    fact      F*      ★ 참이지만 아무도 안 꺼냈을 수 있다.  known_by = []  ← 자원
    open      [ ?? ... ]              현재 뚫려 있는 구멍
}
```

### `depends` 가 이 도메인의 핵심이다 ★

주장은 대부분 **안 적은 전제** 위에 서 있다.
그리고 진짜 토론은 결론이 아니라 그 전제에서 갈린다.

```
✗  claim C1 { text = "규제를 완화해야 한다" }
      → 공격할 데가 없다.  근거를 대면 근거 싸움만 난다.
      → 서로 다른 세계관을 갖고 같은 단어로 싸운다.  ← 산문 토론의 실패

✓  claim C1 {
       text    = "규제를 완화해야 한다"
       scope   = [ 신규진입_장벽 ]
       ground  = [ G1 ]
       depends = [ P1, P2 ]
   }
   premise P1 { text = "진입이 늘면 경쟁이 는다",     val = true,  hidden = true }
   premise P2 { text = "경쟁이 늘면 소비자가 이득이다", val = ??,   hidden = true }
                                                        ↑ ★ 여기가 진짜 쟁점
```

**전제를 드러내는 순간, 싸울 자리가 정해진다.**

**처음엔 비어 있어도 된다. 공격받는 순간 채울 수밖에 없다.**

```
attack A1  type = premise,  target = C1
   → "C1이 의존하는 전제가 뭐냐"
   → ⚠ depends 가 비어 있다
   → 채운다:  depends = [P1, P2]
   → ★ 그러자 새 사실이 드러난다: P2는 아무도 논증한 적이 없다
   → 그럼 C1은 왜 참인가?  ← 새 구멍
```

**공격이 정의를 요구하고, 정의가 새 구멍을 낳는다.**

### 굴리기가 정의를 검증한다 ★

```
step 4   fn C3.defend()
         ground = [G2]
         ⚠ G2가 P2에 의존한다.  그런데 P2.val = ??
         → 근거가 미확정 전제 위에 있다
         → STOP: ground_rests_on_open_premise
```

**앞에서 통과했던 방어가 나중에 무효가 된다. 그게 맞다.**
**상태를 돌리는 것이 곧 검사다. 별도 검사자가 필요 없다.**

## Q3. AI는 어떻게 도망가는가 → 연산자 ★ 가장 중요

**이 도메인의 도망은 소설과 전혀 다르다.** 꾸미는 게 아니라 **균형 잡는 척한다.**

| 도망 | 연산자 | 강제되는 것 |
|---|---|---|
| "일리가 있다" / "양쪽 다 맞다" | **금지** | 어느 주장이 어느 공격에 어떻게 답했는지 적어라 |
| "맥락에 따라 다르다" | `scope` | 어느 맥락에서 참인지 범위를 적어라 |
| "종합하면" / "결국 균형이" | **금지** | 합치지 마라.  합치는 게 평균이다 |
| 앞 발언에 그냥 동의 | 발언 이력 없음 | 동의할 대상이 상태에 없다 |
| 내용 무관하게 반대 | `attack.ground` 필수 | 근거 없는 공격은 STOP |
| **공격에 답 안 하고 새 주장** | `fn` 강제 | ★ 가장 큰 도망.  아래 참조 |
| "~라고 볼 수도 있다" | `??` | 모르면 모른다고 적어라 |
| 근거 없이 주장 강화 | `ground` 필수 | 뭐가 받치는지 이름을 대라 |
| "설득력이 있다" | `!` cost | 공짜 승리 금지 |
| 수사로 이기기 | `refute` 만 허용 | 죽음은 **논파**에서만 |
| 예쁜 문장 | 칸 없음 | 렌더링에서 붙인다 |

### 화제 전환이 이 도메인의 최대 도망이다 ★

산문 토론에서 AI는 이렇게 도망간다:

```
공격:  "당신 주장은 1998년 사례를 설명 못 한다"
답:    "중요한 것은 장기적 관점입니다.  거시적으로 보면..."   ← 답이 아니다
```

**답한 것처럼 보이는데 답이 아니다.** 그리고 산문에서는 이게 안 잡힌다.

**구조로 막는다:**

```
attack A5 { target = C2 }
   → C2 의 상태가 under_attack 이 된다
   → C2 는 fn 을 통과해야만 상태를 벗어난다
   → fn 은 defend | amend | retract 셋 중 하나만 낸다
   → 새 claim 을 내는 것은 fn 이 아니다.  A5 는 그대로 걸려 있다.
```

**미답 공격이 상태에 남는다. 그래서 도망칠 수가 없다.**

```
□ status = under_attack 인 claim 이 남아 있는가  → 미답.  통과 못 함.
```

```
&        동시에 참인 둘
><       양립 불가
->       함의 (A면 B다)
=>       선택 (골랐다)
??       구멍 / 확정 안 된 전제       ★ 채우면 최악의 위반
?!       논자의 무지 (세계엔 정해짐)   ★ 자원.  reveal 의 연료
!        대가 (되돌릴 수 없다)
X        주장 파기
⊢        근거가 결론을 지지한다
⊬        지지하지 않는다              ★ ground 공격
hooks    앞 공격/주장을 문다
leaves   다음이 물 고리
```

## Q4. "모른다"는 어떤 모양인가

```
??   구멍         아직 안 정했다 / 아무도 논증 안 했다.  → 채우면 위반.  다음 작업이 여기다.
?!   논자의 무지   세계엔 정해져 있다.                    → 자원.  reveal 의 연료.
```

### `premise.val = ??` 가 고민이다 ★

```
P1.val = true    받아들인다
P1.val = ??      ★ 흔들린다.  ← 여기가 진짜 토론이 일어나는 곳
P1.val = false   무너졌다
```

**전제를 boolean 으로 보면 고민이 안 생긴다.**
`??` 구간이 있어야 논자가 망설이고, 망설이면 `amend` 가 나오고,
`amend` 가 나오면 주장이 좁아지고, 좁아지면 다른 주장과의 관계가 바뀐다.

```
step  attack A3  type = counterexample,  target = P2
      => P2.val = ??                    ← 확정 아님.  아직 죽지 않았다

step  fn C1.respond()
      branch  P2.val == true  => defend  ! ground 소비
              P2.val == ??    => amend   ! scope ↓        ← ★ 망설임
              P2.val == false => retract ! cascade

step  fn arguer_B.check()
      when  C1.status == amended         ← ★ 상대가 본다
      => C1.scope 밖을 새 공격 대상으로   ! 없음
```

**연쇄가 저절로 난다.**

## Q5. "무너진다"는 무엇인가 → `refute`

```
refute R<n> {
    trigger   reveal(F*) | counterexample(E*)   ★ 사실에서만
    check     premise.val == false  |  ground ⊬ claim
    effect    claim X  ->  status = dead
    cascade   depends_on(claim) 전부 재검사     ★ 반드시 있다
    cost      arguer.commitments 재검사         ★ 앞에서 인정한 게 발목을 잡는다
}
```

**규율:**
- 죽음은 **`reveal` 또는 `counterexample` 에서만.** 수사·설득·다수결로 죽으면 공짜다. 반려.
- **한 방에 안 죽는다.** premise 가 `??` 를 거쳐야 하고, `amend` 를 거쳐야 한다.
- 죽은 뒤 **cascade 검사**: 그 주장에 의존하던 것들이 전부 흔들린다.
- 그리고 **소급 검사**: 앞에서 그 주장을 근거로 방어한 것들이 무효가 된다.

**refute 는 미리 못 짠다.**
**스텝 검증에서 "이건 안 통하는데"라고 느끼는 순간**이 refute 가 있어야 할 자리다.
그 자리를 찾으면 → 무엇을 알면 죽는가를 역산 → 앞을 소급 검사.

## Q6. "좋다"는 무엇인가 → 통과 조건

**사람이 쓴다. 결과가 아니라 과정에 건다.**

```
PASS
□ 모든 claim 이 최소 1회 attack 을 받았는가          안 받은 주장은 장식이다
□ under_attack 상태로 남은 claim 이 없는가           ★ 미답 = 화제 전환 = 도망
□ 최소 1개 claim 이 dead 되었는가                    아무도 안 죽으면 토론을 안 한 것
□ 모든 dead 가 reveal / counterexample 에서 왔는가   수사로 죽으면 반려
□ 모든 premise.hidden 이 드러났는가                  숨은 전제가 남으면 헛싸움
□ premise 가 ?? 구간을 거쳤는가                      한 방에 뒤집히면 공짜
□ 모든 attack 에 ground 가 있는가                    근거 없는 반대 = 역할 연기
□ 모든 leaves 가 언젠가 hooks 되었는가               미회수 = 버려진 고리
□ 합의문이 생성되지 않았는가                    ★ 생성됐으면 평균화가 일어난 것
□ 순서 독립성:  발언 순서를 바꿔 굴려도 같은 결론인가
   달라지면  → 앵커링이다.  논증이 아니라 반응이었다.   ★ 기계 검출
```

### 순서 독립성 검사 ★ 이 도메인 고유

**소설과 정반대다.**

```
소설:  같은 지점에서 갈라 굴려 결말이 다 같으면  → 가짜 분기.  평균.
토론:  발언 순서를 바꿔 굴려 결론이 달라지면      → 앵커링.  가짜 논증.
```

논증은 순서에 의존하면 안 된다. 참이면 언제 나와도 참이다.
**순서를 바꿨더니 결론이 달라졌다면, 그건 논리가 아니라 누가 먼저 말했느냐가 결정한 것이다.**

이것이 멀티에이전트 토론의 병(첫 발언이 좌표계를 잡는 것)을 **기계적으로 검출**하는 방법이다.

## Q7. "굴린다"는 무엇인가 → 시뮬레이션

**한 스텝 = 한 공격 또는 한 응답.** 시간 단위가 아니고, 발언 단위도 아니다.

```
1. state.now 확인 (주장 그래프)
2. when 조건 맞는 attack / fn 탐색
3. 없으면   → STOP: nothing_fires        ★ 공격할 데가 없다 = 주장이 너무 무르다
   여럿이면 → 갈라진다.  각각 굴린다.
4. attack:  target.status = under_attack + leaves 등록
   fn:      input -> clash -> proc -> branch -> cost -> Δ
5. branch 에 없는 입력 → STOP: undefined_input
6. Δ 적용 — 선언한 필드만.  그 외 = 창작 = 반려.
7. refute trigger 검사 → 발동하면 claim X + cascade + 소급 검사
8. 반복
```

### 시뮬레이터에게 ★

**너는 논증하지 않는다. 코산에 없으면 STOP 한다.**

**예상되는 위반:**
- 공격을 받았는데 코산에 없는 근거를 **지어내서** 방어한다.
  "논리적으로 자연스러워서" 넣는다. → **이게 창작이다. 최악이다.**
- 어느 쪽도 못 이기니까 **"양쪽 다 일리가 있다"로 봉합한다.** → 평균화. 최악.
- 창작하면 구멍이 숨고, **"잘 굴러가네"라는 거짓 신호**가 나온다.

**멈추는 게 성과다. 멈춘 자리가 다음에 쓸 코드가 있어야 할 자리다.**

### 검사자는 없다 ★

**상태(주장 그래프) → 코산 → 상태 이것이 그대로 검사다.**

- 화제 전환하면 → `under_attack` 이 안 풀린다.  STOP.
- 근거 없이 방어하면 → `ground` 가 비어서 STOP.
- 봉합하면 → 죽은 claim 이 0개라서 PASS 실패.
- 숨은 전제를 안 적으면 → premise 공격이 target 을 못 찾아 STOP.

**금지하지 않는다. 불가능하게 만든다.**

## 요청 처리

```
① 공격만 지정      "C1을 쳐봐"
                   → 어느 타입이 통하는지는 굴려서 나온다

② 결과까지 지정    "C1을 무너뜨려"
                   → 역산.  무너지게 하는 사실을 찾는다.
                   → 못 찾으면 STOP: "이 근거들로는 C1이 안 무너집니다"
                   → ★ AI가 "네"라고 안 한다.

③ 상태만 지정      "P2가 쟁점이 되게 해줘"
                   → 그걸 낳는 공격을 지어낸다.  역방향 생성.
```

**요청 하나가 연쇄를 일으킨다:**

```
"C1을 쳐봐"
   → ⚠ C1.depends 없음      (뭘 쳐야 할지 모른다)
   → premise P1, P2 생성     (참조가 정의를 요구)
   → ⚠ P2를 아무도 논증 안 함  (구멍이 드러남)
   → attack A1 type=premise
   → fn C1.respond()
   → ⚠ ground 없음           (방어할 수단이 없다)
```

**하나 넣으면 여러 개가 자라고, 부족한 데가 드러난다.**
